DEPLOYMENT · VULTR · ZERO TRUST · SSO

netbird-vultr

Desired state for one self-hosted NetBird control plane and its identity provider: Traefik, the combined netbird-server, the dashboard, and Authentik with its Postgres and Redis, on a single guarded Vultr instance in Amsterdam.

One process, four services. netbird.bigconfig.online carries the dashboard, the REST API, the management and signal gRPC streams, the relay WebSocket and the embedded IdP, all multiplexed behind Traefik on 443. authentik.bigconfig.online is Authentik, routed by the same Traefik. STUN is bundled into the server on one UDP port; there is no coturn container and no legacy relay port range.

What is tracked here

colors.yml (the only editable desired state), the installed netbird Package Skill payload and lockfile, a root launcher copied from that payload, toolchain files, and documentation. Credentials live in gitignored .envrc.private; generated output in .colors/ is never committed.

Lifecycle

direnv allow
./green build
./green create --dry-run
./green create

Build and dry-run are credential-free and never read ~/.ssh. Real creation converges the instance, its firewall, two unproxied Cloudflare records and the Compose stack, then bootstraps the first owner, registers Authentik as an identity provider, and proves the data plane by enrolling two throwaway peers on isolated networks and checking traffic flows over the relay. Deletion stays guarded by compute-prevent-destroy: true.

Two accounts, on purpose

claude@ululi.it signs in through Authentik and owns the installation. breakglass@bigconfig.online is a break-glass administrator on NetBird's embedded IdP — the only way in when Authentik is unavailable, which is exactly when an Authentik-only account is no use. Desired state refuses the two being equal.

The first converge cannot finish the transfer. NetBird imports an external user only after it has authenticated once, so the run reports a pending manual step and exits zero. Sign in once at the dashboard with the Authentik option, then converge again: the second run approves that user, promotes it to owner and reads the role back.

The machine keypair is not in this repository

This deployment runs in keygen mode: colors.yml carries no vultr-ssh-keys, so the package generates and owns ~/.ssh/netbird-vultr outside the checkout. Cloning this repository elsewhere does not carry machine access — copy the keypair deliberately, or create refuses rather than regenerating a key that cannot reach the live host.

Reaching the host

Convergence writes one ~/.ssh/config block following the workspace SSH Config Standard, so ssh netbird-vultr connects with no address, user or -i flag. The block sits at the top of the file, above any Host * stanza that would otherwise win on User and IdentityFile, and delete removes it before destroying the instance.

Secrets

Most of what this deployment holds is generated on the server and supplied by nobody: the relay authSecret, the session cookie key, the store encryption key, Authentik's SECRET_KEY and database password, the OIDC client secret, and the durable API token. All are create-once — regenerating any of them breaks a running stack while every container stays green.

The backup recovery key is the deliberate exception. Archives carry the whole restore set, so they are encrypted before they leave the host, and the key that decrypts them is operator-supplied rather than generated there: a key generated on the server would be lost with the server it protects.
